# 飞控元件注册与总览（R-MODULES-1）

总览的元件、型号、接口、状态及读数来自飞控注册信息。上位机不维护板卡元件白名单，不从旧 HW 文本补出未注册元件。
注册表示固件配置的组件，不等于已探测到硬件；初始化失败/未启用/等待数据必须明确区分。
本板未配置的外部NOR不得作为GD25Q32故障行出现，参数存储和日志存储按实际后端分别报告。

低频请求保持现有ASCII上行，不启用原本关闭的固件二进制命令解析器：`REGISTRY? <nonce>`。
响应使用既有 `$X` 帧与CRC8，新增二进制function ID `0x2231`（COMPONENTS），单帧payload不超过247字节。
nonce由主机生成并回显；BEGIN/逐项RECORD/END构成完整事务，同一连接和nonce内序号、数量及结束校验一致才替换总览。
不执行固件下发的任意命令字符串；刷新操作只有上述只读请求。

元件记录包含稳定ID、固件给出的名称/型号/接口/阶段/说明、状态枚举、诊断码、采样年龄及有限数量的带标签/单位/有效标识的数值字段。
整数/浮点字段按小端二进制编码；显示格式由通用类型决定，不调用目标端浮点printf。
元件注册表与数据快照不触发扫描、烧录、复位、控制输出或保存参数。
进入总览或在可见页面重连时自动读取一次；后续由“刷新注册信息”或顶部“硬件状态”发起只读查询。
同一时刻仅一个请求，重复点击至少间隔1秒；不周期重发整个注册表。2秒未收齐为超时，3秒前的回包显示过期且遮蔽读数。
未支持注册接口的旧固件明确显示“固件未提供元件注册接口”，不沿用历史固定模块；超时、拒绝、错误帧及校验失败可见。

## 字节契约 v1

所有整数和 IEEE754 float32 均为小端。function ID `0x2231` 在固件 `app_proto.h` 和主机 `proto.py` 同步登记；不改变既有 ID、遥测 schema、日志或参数 ABI。

每个 payload 的公共头是10字节：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | version=1 |
| 1 | u8 | kind：1 BEGIN / 2 RECORD / 3 END / 4 ERROR |
| 2 | u16 | 本次快照元件数量，0～16 |
| 4 | u32 | 请求 nonce，十进制 ASCII 输入并原样回显 |
| 8 | u16 | 索引：BEGIN=0，RECORD=0～count-1，END=count |

RECORD 在公共头后依次为 `<HBBiII>`：元件ID u16（非零且事务内唯一）、状态 u8、字段数 u8（0～4）、诊断码 i32、采样年龄 u32（0xFFFFFFFF=未知）、采样计数 u32。
再跟5个字符串：名称≤32、型号≤24、接口≤24、阶段≤20、说明≤64字节。每个字符串是1字节长度+UTF8原文；名称不能为空。
每个数值字段是标签字符串≤16字节、单位字符串≤8字节，再跟 `<BBI>` 类型、有效标志、32位值。
标签非空且一条记录内唯一。类型为1=u32、2=i32、3=float32、4=十六进制u32；有效位只能0/1，valid=0显示未知，valid=1的非有限浮点数拒绝。
以上各字符串上限并不意味着可以同时取最大长度；整条payload仍须≤247字节，超限显式失败，不截断。

BEGIN没有正文。END正文是u32 CRC32，覆盖本事务按索引顺序的所有完整RECORD payload（含公共头）；反射多项式0xEDB88320、初值0xFFFFFFFF、末尾取反，与Python zlib.crc32一致。
ERROR正文是u32原因：1=导出占用、2=注册冲突/容量错误、3=编码或传输失败、4=请求非法、5=发送预算耗尽。
主机验证版本、数量、序号、长度、唯一ID和CRC32之后才原子替换总览；新请求nonce和连接代次隔离旧帧，采集时的接收时间决定是否过期。

状态枚举：0未知、1已就绪、2等待数据、3未启用、4故障。状态来自固件已有状态，不在上位机凭型号推测。
初始化/接口就绪只代表相应软件事实：DShot完成次数不是电调确认，PWM是指令而非实测位置，蓝牙UART就绪不代表无线连接已建立，电流仍按标称比例、未实测校准。

## 注册、传输与预算

`APP_Components_Register(id, sampler)` 注册仅复制缓存的回调；同ID同回调幂等，同ID不同回调/超容量错误锁存。
发送前冻结注册项列表；采样回调在短临界区内执行，必须无I/O、无等待、无printf，返回的字符串须具有静态生命周期。
编码、CRC和发送在临界区外。注册或查询不启动传感器、不扫描总线、不改变控制输出。
本板注册IMU、气压、磁力、光流、电流、参数存储、日志存储、电调、舵机、遥控、数传、维护接口、状态灯；GPS仅在其初始化入口执行后注册。
型号/接口由固件选择：例如IMU选择实际BMI088/BMI270；参数存储是内部Flash、日志存储是SD。板卡接口名称归BSP，字段和软件状态提供者归App。

普通命令出口用原有USB镜像+UART原始字节队列；维护出口用UART8的有界等待写入，显式传长度，允许0字节。
队列满不删除旧命令、不重放旧快照。FLOG/IMUCAP导出期间返回占用错误。每项前检查300ms发送预算；单次USB等待≤10ms，维护口复用既有单次有界等待，因此总耗时还可能包含最后一次发送等待。
传输失败以完整事务未通过/错误帧计数呈现；没有把某个端口排队成功等同于另一端收到。

ARM ELF离线编码记录：13个元件、15帧、1770字节/次。协议硬上限是16×256+19+23=4138字节/次。
总览没有周期流量（稳态新增0 B/s），保留原UART默认40Hz遥测3356 B/s、58.3%占比。一次典型查询的纯串行时间约307ms（57600、8N1），属于按需突发。
不采用最初草案中的每秒整表刷新：其1770 B/s会把并行默认遥测推至约89%，超过60%稳态预算。查询不会擅自停止或降速用户的遥测流。

## 可复核验证

- 独立黄金字节：`tests/test_component_registry.py::test_independent_golden_bytes`，真实C编码器与独立Python布局及CRC逐字节比较。
- 截断、插入、翻转2000例；缺BEGIN/END、乱序、重复ID、NaN、连接切换、接收延迟、旧固件明确拒绝。
- `test_component_codec_bounds.py` 验证缓冲哨兵、边界、晚注册只进下次快照、预算和传输失败中止。
- `test_component_transport.py` 编译实际C输出路由，验证USB/UART/维护路径的0字节、长度、队列失败及导出占用。
- `test_component_overview_layout.py` 构造真实DronePanel，三尺寸×三缩放、最后一行和横向滚动、选择详情、只查询一次。
- `data/analysis/current/2026-09-13/` 保存ARM前后回包、注册二进制、离线页面截图及测试原文。ARM仿真只注入ADC和捕获出口，不映射外设，不是实机证据。

Contract：只有来自当前连接、完整校验事务的注册项能进入总览；未知值不变成零/正常。
Boundary：纯编解码与注册存储、固件状态提供者、传输出口及通用Tk展示分别独立。
Test seam：实际C编码器→真实传输解析→真实DronePanel；截断/乱序/重复/重连/超时及新未知型号均覆盖。

电流文本诊断的独立修复：newlib-nano未链接_printf_float时，%f会留空；改用整数定点格式保持原CURRENT线上字段，保留nan与未校准语义。
电流计的信号接线按作者确认的原配8PIN完整连接处理，本任务不怀疑或更改硬件接线。
