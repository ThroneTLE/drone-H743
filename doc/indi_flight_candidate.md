# INDI 实机候选固件与频率核查

> 构建日期：2026-07-14  
> 分支：`dev`  
> 基线提交：`bc12925`  
> 状态：通过主机测试与固件编译，但尚未通过真实旋翼飞行验证。

## 1. 结论

当前应上机验证的是**固定参数固件式 INDI**，不是 INDI+LESO，也不是自适应 INDI-RLS。

这里的“最优”只表示：在目前建立的候选算法和仿真边界中，它是最稳妥的实机候选，并不表示 INDI 在所有模型、所有参数和所有飞行器上全局最优。

| 控制器 | 工程预期范围稳定率 | 工程范围 95% RMSE | 物理可行极端范围稳定率 | 当前判定 |
|---|---:|---:|---:|---|
| 固件式 INDI | 100% | 6.467° | 70.0% | 本次实机候选 |
| INDI + LESO | 100% | 6.168° | 58.7% | 暂不上机 |
| 自适应 INDI-RLS | 100% | 11.500° | 56.7% | 未通过收敛门槛 |

极端测试里包含惯量、推力、控制效能、舵机时间常数、命令延迟、陀螺零偏和外扰同时随机。固定 INDI 的工程范围误差略高于 INDI+LESO，但在更宽的物理可行范围内稳定率更高，因此本版不引入 LESO 或在线 RLS。

> 上表仿真使用原 `±30°` 倾转限幅。当前固件已缩小为 `±18°`，控制器排名仍可用于算法选择，但这些稳定率不能直接作为新限幅的定量飞行证明。悬停附近 `g·tan(18°)≈3.19 m/s²`，仍高于当前水平速度环 `2.91 m/s²` 的输出限幅。

## 2. 硬件频率是否满足 INDI

### 2.1 IMU 与控制计算

| 环节 | 当前频率/周期 | 判定 |
|---|---:|---|
| ICM42688 采样目标 | 1 kHz / 1 ms | 满足角速度差分采样需求 |
| 姿态控制计算 | 500 Hz / 2 ms | 满足当前离散 INDI 仿真步长 |
| INDI 异常 `dt` 回退 | 2 ms | 与控制周期一致 |
| 陀螺低通 | 80 Hz | 为角速度输入预滤波 |
| INDI 角加速度低通 | `alpha=0.85` | 500 Hz 下等效截止频率约 12.9 Hz |

因此，H743 算力、IMU 采样和控制任务频率满足当前 INDI 的计算要求。

### 2.2 舵机总线真实上限

两个舵机合成一帧发送：

```text
{G0000#001PxxxxT0000!#002PxxxxT0000!}
```

一帧长度为：

```text
6 字节帧头 + 2 × 15 字节舵机命令 + 1 字节帧尾 = 37 字节
```

UART7 为 115200 baud、8N1，每字节在线路上占 10 bit：

```text
t_frame = 37 × 10 / 115200 = 3.212 ms
f_bus,max = 1 / t_frame = 311.4 Hz
```

控制任务每 2 ms 尝试发送一次，但 DMA 忙时会跳过该次发送。目标连续变化时，实际通常会形成约 4 ms 一次、约 250 Hz 的成功发送节奏，而不是物理上的 500 Hz。

已测舵机一阶时间常数约为 `0.176624 s`，对应一阶机械带宽约：

```text
f_servo = 1 / (2π × 0.176624) ≈ 0.90 Hz
```

所以当前瓶颈不是 MCU，而是舵机机械滞后和串口传输延迟。约 250 Hz 的命令更新率远高于约 0.90 Hz 的机械带宽，但执行器相位滞后仍是实机最主要风险。

### 2.3 频率判定

- **计算侧满足**：IMU 1 kHz、控制 500 Hz。
- **总线侧不可能达到 500 Hz**：理论上限 311 Hz，持续变化时预计约 250 Hz。
- **仍可进入小范围系留验证**：总线更新率相对舵机机械带宽足够高，且仿真已包含 0--16 ms 命令延迟。
- **不能据此宣称飞行安全**：当前实现没有完整论文式 INDI 常见的控制输入与角加速度匹配滤波，也没有显式舵机状态观测和执行器逆模型。

## 3. 本版控制器参数

| 参数 | 当前值 |
|---|---:|
| INDI 默认状态 | 启用 |
| 横滚/俯仰惯量 | `0.019 / 0.019 kg·m²` |
| 姿态误差增益 | `16 rad/s²/rad` |
| 角速度阻尼增益 | `6.4 rad/s²/(rad/s)` |
| 角加速度低通系数 | `0.85` |
| 单周期修正增量 | `±1°` |
| 累计 INDI 修正 | `±10°` |
| 修正泄漏 | `0.5 Hz` |
| Roll/Pitch 控制效能极性 | `+1 / +1`，保持现有正确极性 |
| 最终倾转限幅 | `±18°`（原 `±30°` 的 60%，同时作为固件硬上限） |

控制律为：

```text
angular_accel_raw = (gyro[k] - gyro[k-1]) / dt
angular_accel_hat = alpha × angular_accel_hat_prev
                  + (1-alpha) × angular_accel_raw

virtual_accel = 16 × (angle_ref-angle) - 6.4 × gyro
effectiveness = total_force × lever_arm / inertia
delta_tilt = clamp((virtual_accel-angular_accel_hat)/effectiveness, ±1°)
tilt_correction = clamp(leak × tilt_correction_prev + delta_tilt, ±10°)
```

## 4. 本次固件新增保护与诊断

1. INDI 收到 NaN/Inf 的传感器或模型输入时，不再让异常值污染角加速度差分器和累计修正。
2. 异常时清空 INDI 内部状态，退回有限的基础倾转命令；下一帧有效数据重新初始化。
3. 保持 INDI 默认启用，保持 Roll/Pitch 原有正确极性，未修改已仿真的增益和限幅。
4. 新增只读命令 `SERVO STATUS`，可查看真实 DMA 发送计数、忙计数、错误计数、帧长和波特率。
5. `INDI?` 与 `SERVO STATUS` 均可经 Ai-WB2 控制通道转发。

## 6. 烧录后无桨检查

必须先拆桨或完全断开旋翼动力，并固定机体。

1. 发送 `PARAM?`，确认至少以下项目：

   ```text
   coax.indi_enable = 1
   coax.indi_roll_effectiveness_sign = 1
   coax.indi_pitch_effectiveness_sign = 1
   coax.indi_roll_inertia_kg_m2 = 0.019
   coax.indi_pitch_inertia_kg_m2 = 0.019
   coax.tilt_limit_rad = 0.314159
   ```

   FLASH 中已保存的 V8 参数可能覆盖编译默认值。任何一项不符合预期时，不要直接试飞。

2. 发送 `IMU?`：初始化必须成功，静止时角速度不能持续漂移或跳变。

3. 保持未解锁、拆桨状态，短暂把油门越过 20% 稳定控制门槛，发送 `INDI?`：

   - `active=1`；
   - 静止时 `roll_accel`、`pitch_accel` 不应持续出现巨大尖峰；
   - `roll_correction`、`pitch_correction` 不应静止贴住 `±0.1745 rad`。

4. 手动小角度倾斜机体，检查舵机动作必须产生恢复方向。当前极性没有改动，但烧录后仍必须以机构实际动作复核。

5. 连续活动机体时，间隔约 10 秒发送两次 `SERVO STATUS`。实际成功发送率计算为：

   ```text
   servo_rate_hz = 1000 × (tx_done_2-tx_done_1) / (tick_ms_2-tick_ms_1)
   ```

   预期 `last_len=37`，`err=0`，`recover=0`。持续变化时约 200--300 Hz 是合理结果；`busy` 增长并不一定是故障，它表示 500 Hz 尝试发送时上一帧仍在传输。

## 7. 首次系留试飞边界

- 只做小角度、短时间、低高度系留，不直接自由飞行。
- 第一次只验证恢复方向和是否出现持续振荡，不验证高速跟踪。
- 发现高频摆动、舵机敲击、修正长期贴住 ±10°、IMU 异常、串口 `err/recover` 增长或遥控失联，立即降油门并上锁。
- 当前仿真仍未完整接入真实共同油门推力曲线、舵机频响离散数据和机架柔性，因此不能省略台架与系留阶段。
