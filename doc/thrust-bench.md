# 共轴桨推力与功耗辨识

本工具针对上下两片桨均保持安装的台架。称重测量安装结构上的总轴向力，带载电压沿用电压测量，DShot提供两路电转速和两路ESC电流。模型直接使用eRPM，不换算机械RPM，不需要磁极数或极对数；KV估计不参与拟合。板载总ADC电流仅诊断，不能替代DShot电流。

软件交付状态以 PIPELINE 的 R-THRUST-2 为准。软件测试、构建、台架实测和飞行验收是不同证据。程序输出的是离线候选模型，不会替换当前飞行控制推力表或保存 Flash。

## 日常工作流程（2026-09-22 已采纳）

原称重窗口现在以“采集 → 实验库 → 训练与效果”为默认工作流。试转映射与手动控制默认折叠，称重标定功能和历史记录不变。

1. 连接台架，默认任务是“自动补数（换电继续）”：给出本次最高油门和3S带载换电电压（默认10.8V，可改）。程序按同装配历史有效点和当前实测电压寻找缺口，并以已测可达的电转速为目标调整两路指令；无历史点先短时探索，若用户明确提高本次最高油门，则以单次不超过1%油门的已确认SET逐步探测新增转速范围。也可选快速检查（5点，只检查链路响应）、标准采集（4×4完整16组合）或补充测量。预览不出油门，点击开始才运行，绝不自动提高上限。
2. 自动补数逐点调油门追踪已实测可达范围内的两路eRPM；每次调整不超过1%且有界，不可达不继续追高。转速和称重有足够独立更新且稳定后尽快收满可训练的稳态段；有效但不稳定在有界时间内跳过并说明，等待样本以settle记录。核心来源失效仍立即结束并STOP。补测只是指令工况筛选，不能替代模型转速域覆盖检验。
3. 自动补数达到带载换电电压、每轮最长时间、点数上限或用户停止时发STOP；达到换电阈值时提示用户换电，只有用户再次点击“开始 / 换电继续”才恢复。本次电压/时长/点数阈值不得在运行中被输入框悄悄改变。每轮结束自动索引入本地实验库；打开“实验库：选择训练与验证”会刷新历史。每行一轮，可用 Ctrl+A 全选，分配训练、验证或暂不使用；“删除选中”会从实验库和训练/补测中隐藏所选轮次，勾选“显示已删除”后可恢复，原始会话文件不变。库中按当前实测电压和已记录 eRPM 范围显示预设目标总数/尚缺数，这是当前电压附近的采集规划，不是模型全域完成判定。新实验默认待分配，可用于自动采集覆盖规划但不参加模型训练；用户明确设为“暂不使用”的轮次也不参与覆盖规划。不把失败实验直接扔掉，保留其中有效稳态段。不同装配/测量快照身份不得静默混用。
4. 训练使用所选整轮的固定版本，验证轮不会混入系数拟合或训练缩放。比较仅eRPM与连续实测V两个候选，无需填写人工电压层；验证用于候选选择，最终可靠性仍需新独立复测。旧电压分层分析入口和产物保留为兼容工具。
5. 每轮自动采集结束后同时显示采集器记录目标数与实验库确认的可用稳态点数，并更新当前电压附近的缺口。报告先解释用了几轮、平均/95%误差多少克力、实际适用范围和下一步补测，再看实测/预测、残差与覆盖图。局部可用、仅训练、域外拒绝分别呈现，不用一个“不可用”遮住所有测量。

确认的STM32 USB CDC默认以30Hz请求快照，其他链路15Hz；只有真实的DShot转速与RS485称重独立更新才形成有效点。自动补数把已实测可达的上下桨电转速范围各划成五级，形成最多25个双路组合；不是按0～100%逐个百分点扫描。当前电压附近的已有覆盖按转速网格单元判断（不把300eRPM级微差当成全新工况），但是否达到精度目标仍看独立验证；完成的目标在本电压阶段不因瞬时电压波动重新排队；平滑后的带载电压累计下降约0.3V才开始下一轮。两轮测点之间的耗电保持选择已有实测、双桨均转的工况，优先靠近本次最高油门的80%，保持值同时不超过50%绝对上限与本次最高油门；例如本次最高20%且已有15/15实测时保持15/15。等待提示每电量段只发一次，低压阈值、ACK和停止保护保持原定义。当飞控健康监控因eRPM或V回读超过新鲜度门限而STOP时，自动采集不把清空后的None强制转float，也不覆盖板端失效原因；活动期源年龄门限仍为250ms。若短暂排队的回包正由FC接收线程处理，健康检查最多等10ms后按相同门限复查；仍无新鲜数据就STOP。此类STOP进入“等待恢复”，原始CSV和已完成稳态段保留；只有用户点击继续且电压、上下桨eRPM、称重和旧控制租约都已恢复，才重新ARM，失联与低压不自动重启。每条样本保留真实测得的带载电压，0.3V只决定补采时机。模型报告以整轮留出最大单点绝对误差≤50克力且验证覆盖达到门限作为作者指定的选择验证目标；选择验证达到目标后仍需要全新独立测试轮。原始CSV/JSONL不改写。`data/identification/thrust/experiments.sqlite3`保存索引、用途选择和不可变轮次快照；历史文件增长后已选版本不变，列表提示重新选择用途可更新。模型及报告位于`data/identification/thrust/models/YYYY-MM-DD/training-*/`，内含来源清单和数据指纹，不自动下发飞控。

## 使用入口

在仓库根目录运行 `python tools/pressure_rs485_gui.py`，`python -m tools.thrust_bench` 也打开同一个入口。窗口保留原称重与H743连接，主流程为智能采集、实验库选择、训练与效果；试转/手动和自定义旧扫描位于展开设置。原ESP控制和旧油门扫描已从窗口移除，默认不连接任何设备。

先读取重量，放已知砝码、填写克数、点击“采集标定点”，沿用原来的标定操作。已有校准自动加载；台架会话复制不可变标定快照，不要求管理JSON，不重写旧校准，也不重新拟合原分段曲线。单点沿用原来的过零比例假设并记录来源；建议补空载和多个已知重量点。

停止独立称重读取后，选择H743串口和本次油门上限，再连接台架。会话会继续实时称重，同时显示上下桨eRPM、带载电压、两路DShot电流及有效配对后的合计电流和输入功率；无效、过期或断开的数据清为空缺。上下桨映射取飞控确认值。连接期间不再另开称重串口，原“去皮”按钮转为同一会话的软件去皮，且必须先停止电机；修改砝码点或置零/写传感器标定需要先断开台架会话。

手动控制先“台架解锁（零油门）”，再调整上下桨目标，点击“应用上下桨油门”；拖滑杆本身不输出。保持时间到达后自动停止，手动控制与自动扫描互斥。窗口底部“立即停止上下桨”常驻，滚动时也可操作，并同时取消手动/扫描。停止后的迟到确认不得恢复输出，断连后不自动恢复。自动扫描与生成模型使用既有实测采集/离线模型模块，详细网格、电量层和采样频率放在可展开设置中。

历史CSV的事后查看函数继续供 `tools/thrust_ident_auto_viewer.py` 使用，不接入本窗口的执行器控制或实测模型。

### 逐通道确认映射与解锁

在同一原窗口内，先连接H743，查看“逐通道试转与上下桨映射”的通道1/2原始eRPM。固定台架并清场后，勾选确认，分别点击测试通道1和2（默认5%、1.5秒，上限20%、3秒）。观察实际转动的是上桨还是下桨，以及从上往下看的旋向，然后手动选择。旋向选择只声明观察结果，不修改电调转向，也不根据转速大小猜桨叶位置。

点击“提交映射到RAM”，两路角色与旋向整表回读一致且飞控确认后，才能进入“台架解锁（零油门）→应用上下桨油门”。“确认后保存到Flash”是单独的用户操作，不会自动保存。已采集扫描数据后禁止在同一会话改映射；应断开重连建立新会话。读取已有映射也须显式点击，不会覆盖正在编辑的选择。

点转使用既有PROPCAL窗口，与TBENCH手动/自动扫描互斥，共用原连接和接收队列。固定底部停止按钮覆盖三种操作。停止先发安全STOP，再排空旧工作线程；旧操作不得在停止或重连后补发ARM、SET、COMMIT。实际拒绝原因持续显示，不被随后的空闲回包盖住。

### 旧电压分层报告与自定义扫描（兼容入口）

扫描停止后点击“生成模型报告”，再点“查看拟合效果”。每次生成独立报告目录，显示实测对预测、残差、实际电压与eRPM覆盖，以及独立留出误差。报告区分训练拟合和整轮/电压层留出；没有独立验证时明确标为未验证，不能靠训练误差判断够用。保持原称重标定功能和数据，不添加新的称重标定检查。

静态双桨模型主要采二维网格，在多个实际带载电压范围重复；无需为了该目标跑完单桨和动态阶跃。单桨用于单驱动安装状态模型，阶跃用于动态模型。25个非零组合、3个实际电量范围和额外独立复测只是起步规划，不是录够行数就合格。每个稳态段的高频行先聚合，重复工况不等于更多不同组合。

电池放电必须逐点使用实测电压，并在不同电量下重复相近转速区域，避免电压与转速变化混淆。当前算法仍有电压层内跨度与层间分离限制；报告会展示不满足项，不将任意放电曲线自动视为可建模数据。至少三个实际层才能留出中间层检查插值；边界电压应通过独立重复轮次验证。在展开设置中点击“准备从首层独立复测”可保留本会话旧数据、从首层重新记录；它不启动电机，调整真实电量后仍需手动开始扫描。

本次用户设备为 **AEO CRM2413-KV1300**。按作者确认，所有当前采集/预测直接使用电转速eRPM；界面不再要求磁极数/极对数，不存在默认填1或猜测磁极数的换算。电流拟合只使用DShot分路反馈。双向 DShot 回读（BITBANG 后端，R-DSHOT-5）已于 2026-09-21 实机打通，2026-09-22 起的台架实测使用两路实测 eRPM；本工具不改固件或线上协议解码。

每次扫描前先确认本次油门上限与计划范围。普通旋向检查仍用原来的单路20%窗口；推力台使用独立的 TBENCH 窗口。台架 ARM 本身只进入零油门待命，合法双路 SET 才更新目标；300ms心跳、互斥与输出错误关闭由固件执行。连接恢复后需要重新确认，程序不自动重放旧的扫描命令。

默认快照15Hz；目标SET与心跳合计最多10Hz，完整双向预算约3405B/s。超过数传预算的高速配置只允许已识别的STM32应用USB CDC（VID:PID=0483:5740），未知串口或蓝牙SPP会在打开端口前拒绝高频。动态辨识建议使用确认的USB链路提高采样率；结果仍以真正独立的RPM更新时间为准。

同一计划应在不同真实带载电压条件下重复，并记录独立轮次；修改电压标签并不会改变实际电压。实测两路转速和电压覆盖不足时，程序保留原始数据并说明缺口。

离线报告可以独立生成：

```powershell
python -m tools.thrust_bench analyze <session>/samples.csv --metadata <session>/metadata.json --output <new-report-directory>
```

输出目录必须是新的目录，包含 JSON 模型、Markdown 报告和有数据时的图。查询 API 为：

```python
from tools.thrust_bench.model import analyze_samples, predict_thrust

analysis = analyze_samples(samples, metadata)
thrust_n = predict_thrust(
    analysis, upper_erpm=measured_upper_erpm, lower_erpm=measured_lower_erpm,
    voltage_v=loaded_voltage_v, mode="dual",
)
```

单驱动使用 `mode="upper"` 或 `"lower"`，被动桨转速可缺失；结果仍是当前双桨安装结构的总测力。禁止用 KV 估计填写 measured eRPM 字段。

## 测量含义

- 上桨驱动、下桨不驱动：测到当前安装状态的总力，下桨可能挡流或被动风车转动。
- 下桨驱动、上桨不驱动：同样属于安装状态基线。
- 双桨共同驱动：需要两路独立变化的工作点，只有等油门的一条扫描线不足以确定二维推力面。
- 两路DShot电流分别拟合。只有两路都有效、新鲜且时间对齐时才求和，再与对齐的带载电压计算输入功率 V×(I上+I下)；不据此声称分别测出了桨叶推力、轴功率或偏航力矩。
- 未驱动通道的 DShot 停转回包表示电调未报告换相转速，不是另一片桨物理静止的独立测量。

首次测量前记录桨叶规格、间距、安装姿态、称重标定和上下桨的已确认ESC通道。DShot电流模型可以按遥测安培尺度拟合，但未取得外部仪表证据时明确标为“未外部校验”，不能从板ADC校准标志推导ESC电流已校准。当前TBENCH v1电流字段为整安，元数据保留1A分辨率来源；不虚构更细精度。

## 数据质量

每次会话保留元数据、逐样本CSV、异步来源原始记录和事件。主机记录使用schema v2，明确upper_erpm/lower_erpm及分路ESC电流/年龄；旧v1机械RPM不能自动改名混入。板端TBENCH线协议仍为既有v1，主机记录版本不是要求固件改协议。数据写入 `data/identification/thrust/YYYY-MM-DD/<unique-session>/`，不会覆盖旧数据。不同电压层和独立重复使用不同 run_id，单一工作点或阶跃使用 segment_id。

主机单调时间与飞控毫秒计时属于不同时间域。关联样本依据请求 nonce、接收代次、来源年龄和明确的时间对齐界限；不能把收到同一旧值的次数当成采样率。RS485 内部滤波、称重有效更新率及 DShot 丢回包必须进入有效频率判断。

先完成稳态扫描，再在常用工作点附近进行小幅上升/下降阶跃。动态模型优先使用转速的真实更新，不把秤的迟滞当作电机惯性。样本过稀、有间断、激励不足或二维数据退化时，报告说明不能辨识的原因。

## 模型边界

主要标定结果显式接受带载电压：双驱动 `T_total=f(eRPM_upper,eRPM_lower,V_loaded)`，单驱动 `T_total=f(eRPM_active,V_loaded)`。各层拟合使用电转速eRPM，相邻层按真实电压中心插值；原仅RPM曲线保留作比较。电压标签只作分组，不能替代实测V。分路电流为 I上/I下=f(eRPM上,eRPM下,V)，输入功耗只使用同步的V与两路DShot电流，不对RPM推力再固定乘V²。

验证按整轮或电压层留出，报告区分训练误差和独立验证误差。模型只描述记录的安装配置与覆盖范围，不外推成高速前飞、下降来流或其他桨间距下的已验证模型。省电转速配比也不代表偏航力矩已经平衡。

内部协议、观测类型和模块职责见 [接口约定](thrust-bench-contract.md)。

## DShot电流预测

`predict_current(analysis, upper_erpm=..., lower_erpm=..., voltage_v=..., role="upper"|"lower", mode="dual"|"upper"|"lower")` 使用电转速和带载电压，查询超出已测覆盖范围时拒绝外推。缺失一路电流不填零、不用板总电流替代，也不阻断仍有效的推力模型。不同电量层标签不能代替真实电压。

## 扫描换档与心跳协调

扫描/手动SET与保活心跳共用同一发送节拍和确认槽。换档等待者优先，心跳正常让位不视为发送失败；取得发送位置后才读取最新心跳目标，避免旧目标覆盖新档位。总SET频率仍最多10Hz，ACK超时仍250ms，板端300ms看门狗不变。真实ACK超时先取消等待者再STOP，不允许等待中的换档补发。

故障日志区分“未取得发送位置”（set_not_sent）、“命令未入队”和“已发送但ACK未匹配”。发生错误仍停止扫描；不能靠忽略确认或扩大超时继续输出。
