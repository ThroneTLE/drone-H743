# 验证策略：默认定向，极少数情况全量

本文件是测试时机与范围的唯一流程来源，主模型负责最终审核，执行者及协助复核的模型共用。
原则：**默认只跑受影响范围的定向验证**。只有特别大的架构改动，导致多个核心路径同时重组且无法可靠圈定受影响测试，或作者在本次任务明确要求，才跑 `python -m pytest tests -q`。阶段交审、整批交付、准备烧录/发布、协议或配置升版、安全相关局部改动，都不凭类别自动升级为全量；它们需要更充分的专项测试和相应构建。判断整个交付相对基线的累计影响，不按行数或拆出的子任务数降低专项验证。

## 选择范围

| 情况 | 必做验证 | 不自动触发 |
|---|---|---|
| 讨论、只读分析 | 核对所用事实 | 测试、构建、索引生成 |
| 仅文档、提示词、注释，无可执行输入变化 | 链接/格式及相关文档契约；改 SKILL 检查入口与规则一致性；主控收尾生成索引 | 全量 pytest、固件构建、新增凑数测试 |
| 局部上位机/工具功能，接口和职责不变 | 本模块、受影响调用方及原行为回归；UI 行为用真实 `DronePanel()` 验证 | 固件构建、无关页面矩阵、全量 pytest |
| 局部固件实现，公共约定与安全行为不变 | 相关真实 C 测试、调用链与兼容性回归；受影响配置的 Debug 增量构建，零警告 | 无关配置构建、全量 pytest |
| 协议/持久化格式变化，或安全/坐标/执行器局部行为变化 | 受影响的真实编解码/配置迁移、故障回退、调用链与负例测试；相关固件 Debug 零警告构建及专属契约 | 因关键字触发全量 pytest |
| 阶段交审、整批功能交付、准备烧录或发布 | 在最终组合上重跑受影响的定向测试、所需构建与专属验收；明确区分软件与实机证据 | 因交付阶段触发全量 pytest |
| 特别大的架构改动：多个核心路径同时重组，受影响测试无法可靠圈定；或作者本次明确要求全量 | 主控在最终组合上协调一次全量 pytest、所需构建及专属契约 | 子 Agent 各自重复全量 |

纯文档交付适用文档行；多份文档不因文件多而成为运行时大改动。仅上位机交付不编译未变的固件，也不因阶段交付而全量。
“阶段交审”指一次整合验收，验证最终组合中的受影响链路；并非全量开关。主控派单时声明阶段边界，累计影响扩大时扩展**相关专项测试**。只有达到上表的特别大架构改动判据才升级全量。
一次改符号/安全常量即使只有一行，也要测其旧行为、负例和受影响链路；分析或仅描述它并不等于修改其行为。
脚本、测试装置、构建/生成配置和测试依赖属于可执行输入，不能伪装成纯文档。专属黄金向量、真实 Tk、真实 C、兼容性和实机判据不因分级而省略。
作者当次明确要求的检查优先；作者当次明确说“不做全量”时停止/不启动全量。旧任务卡或类别文档中的通用“全量”措辞不自动覆盖本策略；真实 C、兼容迁移、黄金向量、实机和特定配置构建等**专属判据**仍须完成，不以省时为由跳过。

## 开发与合并

1. 主控按基线与预期影响选相关测试，说明“测什么、为什么”；执行者发现影响扩大时向主控升级，不自行漏测或顺手改其他模块。
2. 执行者运行定向测试并保留命令、退出码、原始输出、代码版本及配置。修 bug 同时覆盖原问题和应保留的旧行为；测试基准来自真实格式/实现/数据。
3. 主控逐项看差异和原始输出，合并后检查模块配合。局部结果不能证明最终组合；冲突修复或接口接线必须重新验证受影响链路。
4. 主控先列出受影响链路的定向测试；只有满足上表的特别大架构改动或作者当次明确要求时才统一执行 `python -m pytest tests -q`。需要固件构建时执行 `cmake --build --preset Debug`，新工作树先按 preset 配置，不借用其他目录的构建缓存。任务要求的多配置各用独立构建目录。
5. 测试前完成必要索引生成，避免索引新鲜度检查假红。记录结果后只改进度/证据文档的，重建索引并补文档检查即可，不因记录结果重跑无关测试。

## 结果复用与失败

- 结果仅对已验证的源码、测试、依赖、配置、输入数据和工具环境有效。记录提交号；未提交内容需附差异指纹/清单。不得只看“上次通过”。
- 后续只改说明文字时复用仍有效的代码检查；相关实现/测试/配置改变后补跑受影响检查。若一时无法界定影响，先分析依赖并扩大定向范围；只有特别大的跨核心架构改动才用全量兜底。
- 子模型结束后，主模型核对最终版本与原始输出，可复用同一输入与环境下的有效结果并做重点复核；证据不足、环境差异或发现新问题时补跑。作者要求独立复跑时照办。
- 已有测试足够覆盖行为时复用；缺口才新增。不可删除保护、放宽阈值、跳过失败或只改预期来制造通过；既有失败也应如实报告，不能算全绿。
- 一次通过后不无理由反复扩大或重跑。编译错误先解决再继续；失败信息交回主控分配，不让所有 Agent 一起修同一失败。

## 证据与并发资源

- 子 Agent 完成后返回输出与限制，状态为待审核；主模型审核最终组合与全部判据后决定通过/返修，并统一更新 PIPELINE、本批汇总及索引。只有判据齐全才置 ✅；实机证据单列，未取得时不得将包含实机要求的任务整体标为通过。
- 每个工作树使用自己的构建目录、临时文件、测试数据和输出路径；回环端口必须独占/动态分配，不能默认所有任务占同一端口。
- 普通模块测试可并行；重构建、例外全量回归、GUI 性能基准由主控安排，避免同机资源竞争污染测量。禁止并行抢占目标板、串口和烧录器。
- 交付简述已验证范围、未运行项及原因、结果与日志路径。定向验证通过就如实称“定向验证通过”，不把未跑全量或未做实机验收说成已通过。

## 并行与慢界面测试（2026-09-29）

- 已装 pytest-xdist：`python -m pytest -n auto --dist loadfile tests`，`-n auto` 在 `tests/conftest.py` 里封顶 **2** 个进程、工作进程自降为低于正常优先级；护栏计数由各工作进程交回主进程汇总。
- **任何全量或并行测试都要作者当次同意并由作者选时间**：2026-09-29 20 进程、以及 6 个低优先级进程（强制跑开真窗口的测试）都让作者电脑卡死，作者杀掉测试后立即恢复——真窗口的负担在窗口系统/显卡，进程优先级管不到，现场编译的测试程序还会被 Windows Defender 扫描。
- `@pytest.mark.slow_ui`：真面板"尺寸 × 缩放"布局矩阵等慢测试。默认 `--slow-ui=auto`，只有 `tools/panel_lib/`、`tools/drone_tcp_panel.py`、`tools/panel_qa/` 相对 HEAD 有改动时才跑，否则跳过并写明原因；`--slow-ui=on/off` 强制。改界面布局时照常跑它们，别用 off 掩盖。
