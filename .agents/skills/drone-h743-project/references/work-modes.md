# 执行者工作模式

本文件定义执行者会话可以进入的三种模式、各自的授权边界和退出条件。
默认处在「常规 REQ 模式」；另外两种由**明确触发条件**进入，不能凭感觉切换。

进过哪些模式、每次为什么进，必须写在交付说明里。审核者按本文件的判据验收。

| 模式 | 触发 | 核心授权 | 退出 |
|---|---|---|---|
| 常规 REQ | 作者派单 | 按 REQ 改代码 | REQ 置待审核 |
| 算法验证 | REQ 目标是"确认算法在真实数据上的行为" | 建离线分析/回放链路 | 交出同数据集对比结论 |
| 修 bug | 计划外缺陷挡住了路 | **可以动手修**，不再只是上报 | 单独提交后回到原 REQ |

---

## 1. 常规 REQ 模式（默认）

任务来源是 `PIPELINE.md` 的执行需求清单。

- 作者**可以一次派发多个 REQ**，你连续做完一次性交审；不必做一个停一个。
- 没指定时，取当前主线节点直接需要的、状态为「待做」的〔码〕类 REQ。
- 所有〔机〕〔人〕类 REQ 都不是你的——实机归审核者，物理操作归作者。

---

## 2. 算法验证模式

### 何时进入

REQ 的目标是**判断某个算法在真实数据上表现如何**（估计、滤波、补偿、控制律、
标定解算），而不是改代码结构。

### 授权

- 新建 host 侧回放、复算、对比脚本（放 `tools/`，遵守新功能新模块）
- 只读读取 `data/**` 下的全部历史记录与飞行日志
- 用 Python 独立复算一遍固件里的同一段数学，做数值交叉验证
- 建离线 harness，把固件的 C 函数直接编到 host 上跑

### 判据（验收看这几条，不看"测试绿不绿"）

1. **结论必须落在实录数据上。** 自己构造的输入只能用于单元测试，
   **不能**用来下"算法正确/收敛/达标"的结论。这条没有例外。
2. 必须给出**基线版本与待判版本在同一份数据上**的逐项对比，
   而不是各跑各的数据集然后比结果。
3. 必须写清**失败模式和适用边界**：这个算法在什么条件下不成立。
   只报"通过"而不报边界的交付一律打回。
4. 数值容差要说明**来源**（传感器量化、定点精度、采样率），
   不许先看到结果再倒推一个刚好能过的阈值。

### 不许做（未经作者单独批准）

- **改控制律、滤波器系数、PID 参数**——那是冻结副线 S4/S5。
  「验证」不等于「整定」：你可以证明当前参数好或不好，
  但换参数是另一件需要立项的事。
- 改任何安全门限、判据阈值、坐标符号。
- 拿"算法上更优"当理由绕过 PIPELINE 的节点顺序。

## 3. 修 bug 模式

这个模式存在的理由：老规矩「REQ 之外的发现只写进交付说明、不动手」
在遇到**挡路的缺陷**时会让整条线停摆，或者更糟——让错误结论被当成证据存档。

### 进入条件（满足任一）

- 缺陷**阻塞当前 REQ**，不修做不下去。
- 缺陷让 PIPELINE 里某条验收**永远不可能通过**。
- 缺陷会导致**错误的数据被当成有效证据**保存下来。

> 真实案例（2026-08-30，M5 台架）：上位机解析器只认 `gz_dps`/`gz_mdps`，
> 而固件按 `units=mg_mdps_cdeg` 发的是裸 `gz`。两个名字固件从没发过，
> 于是旋转补偿阶 299 个实采样本无一带偏航角速度，这一阶**从来没有过关的可能**。
> 它不抛异常、不报错，只是安静地让一整阶验收做不完。
> **安静失败比崩溃危险得多**，这类缺陷必须当场修。

### 不进入

风格、命名、"我觉得能更好"、性能微优化、想顺手做的重构——写进交付说明，不动手。

### 流程（顺序不可省）

1. **先固定证据，再动手。** 把缺陷的可观测事实记下来：计数、报文原文、
   复现步骤、受影响的证据文件。修完之后你就再也证明不了它存在过。
2. 定位根因，并回答一句：**"为什么现有测试没挡住它？"**
   答不上来，说明你还没找到真根因。
3. **最小修复面**：只改根因。顺手重构 = 打回。
4. **回归测试的基准必须取自真实来源**——固件源码里的格式串、实录数据、
   硬件回读值。自己编一行样例报文当基准，等于把同一个错误抄进测试里。
5. 单独提交（`fix(...)`），在 PIPELINE 证据表**单独追加一行**，
   写明缺陷、根因、为什么没被挡住。
6. 回到原 REQ 继续。

### 必须升级给作者、不得自行修

即使你确信它是错的：

- 安全门、判据阈值、坐标符号
- CubeMX 生成代码
- `data/calibration/**` 历史证据
- 任何需要动实机才能确认的缺陷（实机归审核者）
