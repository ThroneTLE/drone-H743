# 类别模式：DShot 电调输出

作者在本会话明确批准完整移植计划。本模式覆盖 R-DSHOT-1；不自动授权其他执行器改动。

## 授权与边界

- 从 PX4 v1.16.0 / `6ea3539157ca358c70a515878b77077af7d4611d` 移植单向发送部分，保留 BSD 版权和来源。
- 新建纯协议 Driver、TIM/DMA BSP、契约测试和 CubeMX 配置清单。
- M4/PE9/TIM1_CH1=电调1；M3/PE11/TIM1_CH2=电调2；舵机继续 M7/M8、TIM4、50 Hz。
- 首版 DShot300；最终接入时编译选择 `ESC_PROTOCOL=DSHOT300|PWM`，默认 DShot300。
- 允许回收实际未使用的 UART8_RX DMA1_Stream2 给 TIM1_UP；保留 UART8 中断接收和 TX DMA。
- 必须先交付纯 Driver、宿主测试和配置清单，作者完成 CubeMX 生成后再接入 BSP、输出仲裁及诊断。
- 不手改 Core/USB_DEVICE 生成代码，不烧录、复位、打开物理串口或驱动电机。
- 不改控制律、增益、推力曲线、坐标/极性、安全阈值或历史标定证据；不添加双向 DShot、特殊命令、刷写和运行时协议切换。

## Contract / Boundary / Test Seam

- Driver 接受两路等效 PWM 指令/已验证的 DShot 油门码，输出编码帧及按 CCR1/CCR2 交错的 DMA 字。
- Driver 不含 HAL/RTOS、寄存器、I/O 或全局可变状态；时钟参数显式传入，锁和缓冲所有权归调用者。
- 用宿主 gcc 编译真实 Driver；从冻结上游原函数生成独立对拍装置，再与协议黄金向量核对。
- BSP 接入后测试首末位/预装载、忙拒绝、错误锁存、停止与完成回调竞态、DMA 内存和蓝牙接收。
- 物理禁用与发送停止码是不同状态；两路正常输出在 500 Hz 仲裁提交点成对发帧。

## 验证与交付

- 开发阶段跑负责范围的真实 Driver/BSP 定向测试和所需构建；执行器接入的整批交审由主控按 [验证策略](../validation-policy.md) 验证最终组合的受影响链路。保留最终 DSHOT300/PWM 双配置零警告构建，子任务不各自重复整套。
- 实现阶段分开记录：纯 Driver 完成不等于 BSP 已接入或电调已验证。
- 诊断接入同时进入 protocol-telemetry 模式；旧微秒字段不能装 DShot 码。
- 交付源版本/哈希、BSD 许可、移植差异、测试原文、CubeMX 清单和实机验收清单。
- 全部软件工作完成前保持进行中；子模型完成后交待审核，由主模型核对全部判据决定通过或返修。包含实机要求时，须取得获授权持硬件方的对应证据才能整体置 ✅。
