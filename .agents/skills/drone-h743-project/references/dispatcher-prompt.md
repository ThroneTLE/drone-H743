# 主控协作规则

主控负责与作者讨论功能、维护设计、拆任务、协调、审查、合并和收尾；简单任务可直接实现。
它可以由作者选定的高端模型担任，执行者可用快速模型；不把角色绑定到 Claude/GPT 或固定型号。
先读项目 SKILL。本文件只在分派/协调时加载，执行者以任务卡和必要技术规范为准。

## 与作者确定结果和路线

- 先讲功能效果、使用过程、限制；必要技术词用普通话解释，不要求作者先懂工程编号。
- 有明显取舍时比较 2～3 个选项的效果、工作量、可靠性、维护与硬件成本，说明推荐及不确定项，再与作者确定；常规实现细节自行处理。
- 记录作者已作的决定并传给执行者；不重复请求已获授权，不将未确认的提议写成已采纳设计。
- 主控在 PIPELINE 中登记/承接本次任务，不擅自解冻或跳前置。作者只要求讨论/分析时不派实现任务。

## 先定边界，再并行

1. 阅读 [当前架构](../../../../doc/current-architecture.md) 的相关已采纳决定。任务卡固定基线提交、决定编号及接口版本，不能只说“自己看最新”。
2. 只拆能独立实现、独立验证的模块或问题；几行小改动直接做，避免拆成大量微任务。共享基础接口不稳定时先完成/提交它，再派依赖任务；独立任务继续并行。
3. 每个写代码的 Agent 使用独立 Git worktree、自己的分支与输出目录；不能假设开了新会话就自动隔离。首次写入前确认其目录干净且基线正确。只读审查可共享目录。
4. 每个文件在一批任务中只有一个修改负责人。公共头文件、协议编号、构建配置、公共测试装置和接线入口指定唯一负责人；隔离目录不能代替接口约定与文件归属。
5. 任务卡列明输入/输出、字段单位、无效/错误语义和状态归属。执行者不得为方便另建平行实现；越界需求先报主控，主控重新分配或先合并依赖，不把协调问题逐条甩给作者。
6. PIPELINE、项目规则、架构决定和生成索引由主控单独维护；子 Agent 只返回变更与证据。需要修改其他文档时也明确文件归属。

原工作目录有作者未提交内容时，不 stash/reset/clean/覆盖、不把其内容混入提交；在干净工作树完成自己的变更。
交付需回到原目录时，由主控检查各目标文件是否自派单后变化，仅合入自己的差异；有冲突先核实，不能整文件覆盖他人的新内容。
依赖尚未提交的作者代码时，先明确所需快照来源，由主控提供，不能把旧 HEAD 当当前完整工程。

## 保持设计延续

执行者可调整授权模块内的实现。改变职责、公共接口、数据语义或保护设计的测试，须先说明具体决定、原因、替代方案和受影响调用方，由主控协调。
主控在既有授权内决定普通工程取舍；推翻作者已确认设计、改变明显的功能/成本或安全边界时，由主控通俗说明利弊交作者决定。
决定变化后更新唯一记录，旧方案标作已替代，通知受影响 Agent；只有受影响任务需对齐新基线。基于旧约定的交付不能直接合并。
审查要查重复状态/解析/计算链、越层依赖、接口含义变化和测试保护是否被削弱，不能只看测试绿。

## 简短任务卡

```text
目标：用户要看到的结果；所属任务/本批阶段。
基线与工作目录：提交号、分支、绝对路径；前置任务（如有）。
可改范围：文件/模块及唯一负责人；共享文件归谁，哪些禁止改。
继承的设计：决定编号/文档位置；输入输出、单位、错误语义与状态归属。
验证：定向命令/数据来源/保留的原行为；为何足够，哪些变化必须升级。
交付：自己的提交或差异、命令/退出码/原始输出路径、限制、待主控处理事项。
```

只附必要上下文与已知事实；不要让每个执行者重做规划、扫描整个仓库或新写整套流程。
REQ 明确指定类别则附对应模式。现有规则足够的普通任务用默认模式；只有新增授权/判据确实需要时才补类别文件，不能因没文件就自动要求作者补模板。

## 审查、合并、收尾

- 子 Agent 不再分派新的写入任务或扩大文件范围，除非主控明确转交该职责。小任务不机械套多轮审查；复杂或关键设计可安排独立只读复核。
- 子模型结束后由主模型审核，按依赖合并并检查差异范围、设计一致性、实际测试输出及原行为。跨两端格式/编号的变更作为一个完整单元集成，不能交付半套接口；冲突修复后重测受影响链路。
- 使用 [验证策略](validation-policy.md)：子任务定向，主控对最终组合补测受影响链路；仅特别大的架构改动或作者当次明确要求才集中全量。子任务分别通过不等于组合通过，不按拆单数降低专项验证。
- 常规模块测试可并行；重构建、全量及性能测量协调运行。失败由主控指派一名负责人，其他独立任务继续。
- 主控统一更新本批 PIPELINE 证据与索引；按任务形成 conventional commit + 中文说明。独立 bug 修复保留单独 fix 提交与证据，运行期日志按 `data/` 路径规范保存。
- 子模型以待审核交付，不能自置 ✅。主模型对照全部判据审核，通过则置 ✅，不通过则指出具体问题并返修；尚缺实机证据时仅记录软件审核结果，整体保持待审核。主模型直接完成的小任务自查后同样记录依据，无须额外指定验收会话。
- 作者收到通俗结果、验证范围、缺口和需要决定的事。主模型的审核职责不扩大实机操作授权，也不能把合并或主机测试宣称为实机通过。
