# R-PARAM-1 阻塞缺陷：等值数值回包无法确认

进入横切修 bug 模式：新快速编辑区的正常输入会永久停留在“待确认”，阻塞本项参数写入/回读状态的交付。

先固定的事实见 `parameter-echo-before.txt`：真实 C 控制器接受 0.2，并按当前协议精度读回 0.200000；上位机状态为 target=0.200000、pending=0.2、draft=0.2。随后新增契约测试修复前 4 failed，原文为 `parameter-echo-red.txt`。

根因是 `ParameterEditorMixin._set_param` 用字符串判断待确认值和草稿是否等于回读。已有测试输入与回复都使用同样的小数字符串，新 TCP 测试初稿也把请求格式化成六位小数，所以未触发差异。协议精度来自固件真实 `app_control_format_float` 的 `%s%d.%06u`，测试的值来自真实 C 参数读取。

修复只增加精确十进制数值比较：0.2、2e-1、+0.2000 与 0.200000 相等；不加误差容限，不将不同实际值当作成功，不改固件、写入值或校验范围。回包确认的是已发送值；发送后新编辑的草稿仍保留。新快速编辑区的真实 TCP 测试改用普通数字格式，避免再次掩盖此问题。

聚焦验证 `parameter-echo-green.txt`：33 passed，包括真实 C、草稿隔离、三尺寸×三缩放、真实 TCP/子进程 24 项增益确认。完整回归见 `full-tests.txt`；本修复单独提交，不与旧名称退役实现混提交。

模式：横切修 bug + tk-ui。无实机操作，无算法性能或飞行结论。

末次补充：当旧回包恰好等于发送后新编辑的草稿时，也保留草稿。原先的非确认分支现只在没有待确认请求时清理与目标等值的草稿；最终相关回归34 passed，见parameter-echo-final.txt。
